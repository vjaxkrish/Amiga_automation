# Changes, 20 Nov 2026

**Teaching with the plot map on screen: `teach_gui.py`.** Tested with fake
GPS (demo mode) and against the real 2023 SA NTEP map, not yet in the field.

```
python3 teach_gui.py                        pick the map and start row in the window
python3 teach_gui.py --map "2023 SA NTEP" --start-row 3
python3 teach_gui.py --demo                 fake GPS, try it on the laptop
```

The window shows the whole map. Plots are red until they are taught,
yellow while a mark is averaging, green once taught, and grey if skipped.
The next plot has a blue border. The next plot name and its genotype are
shown large at the top, next to the live fix, satellites, correction age,
heading and wheel speed. Keys are the same as in the terminal: `t`, `m`,
`s`, `u`, `q`, and there are buttons for each.

At the end of each row, on the side where the turn happens, a badge
counts the headland points (`m`) taught for that turn:

| Badge | Meaning |
|---|---|
| grey `0 of 2 m` | row reached, turn not taught yet |
| amber `1 of 2 m` | one turn point so far |
| green `2 m OK` | both points taught: one ~5 m past the row, one lined up on the next row |
| red `!` | the next row was started without both: the robot would cut the corner |

When a red badge appears, the log line and a beep say to press `u`, add
the missing `m`, then `t` again.

It writes the same `~/logs/rover_<time>.json` as `rover_log.py teach
--cols`, so the mission and the camera app need nothing new. The map
comes from the camera app's `plot_maps_config.py`. The search order is
`--maps-file`, then `$TURF_CAMERA_DIR`, then the usual folders under home.
`--rows R --cols C` works without a map file.

## Plots are `t` now, not `n`

`n` sits next to `m` (headland point), so one slip marked the wrong kind
of point. **`t` marks a plot**, in the window and in the terminal
(`rover_log.py teach`). Pressing `n` now marks nothing and shows a
reminder. `m`, `s`, `u` and `q` are unchanged.

## Coming back for a skipped plot

Click a grey (skipped) or red plot in the window. It gets a blue border
marked PICKED, the title reads `NEXT: R1_C4 ... (picked)`, and the next
`t` teaches it. After that the usual order carries on from where it was,
stepping over any plot that is already taught. Esc, `s`, or clicking it
again cancels the pick. A green (taught) plot can't be picked; `u` undoes
the last mark.

**The robot drives marks in the order they were taught.** A plot taught
late is driven late, straight from the mark before it. If other plots are
in the way, first mark headland points (`m`) around them, the same as a
turn. The window says this when you pick. A picked mark is saved with
`"out_of_order": true`, and its plot comes off the skipped list. Undoing
it puts it back on the list.

## rover_log.py

- **The teach logic is now one class, `TeachSession`.** The terminal
  (`rover_log.py teach` and `drive`) and the window both use it, so there
  is one copy of how a mark is taken, named, refused, undone and saved.
  The terminal looks and works as before.
- **The teach file is saved after every mark, skip and undo** (written to a
  temporary file, then renamed). A crash or a flat battery mid-teach no
  longer loses the block.
- **Fixed: `u` after `s`.** Undoing a mark that came before a skip used to
  step the plot name back by one only, so the next plot got the wrong
  name. `u` now undoes the last mark *or* skip, and the names go back to
  exactly where they were.
- **Skipped plots are listed** in the teach file (`grid.skipped`).
- **The next plot steps over plots already taught** (after a pick), so no
  plot is taught twice.
- `pyserial` is only needed when reading the GNSS ports directly, so
  `--demo` runs on a laptop without it.
