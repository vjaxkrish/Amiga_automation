# Changes, 20 Nov 2026

**Teaching with the plot map on screen: `teach_gui.py`.** Tested with fake
GPS (demo mode) and against the real 2023 SA NTEP map, not yet in the field.

```
python3 teach_gui.py                        pick the map and start row in the window
python3 teach_gui.py --map "2023 SA NTEP" --start-row 3
python3 teach_gui.py --demo                 fake GPS, try it on the laptop
```

The window shows the whole map. Plots are red until they are taught,
yellow while a mark is averaging, green once taught, and grey if skipped.
The next plot has a blue border. The next plot name and its genotype are
shown large at the top, next to the live fix, satellites, correction age,
heading and wheel speed. Keys are the same as in the terminal: `t`, `m`,
`s`, `u`, `q`, and there are buttons for each.

At the end of each row, on the side where the turn happens, a badge
counts the headland points (`m`) taught for that turn:

| Badge | Meaning |
|---|---|
| grey `0 of 2 m` | row reached, turn not taught yet |
| amber `1 of 2 m` | one turn point so far |
| green `2 m OK` | both points taught: one ~5 m past the row, one lined up on the next row |
| red `!` | the next row was started without both: the robot would cut the corner |

When a red badge appears, the log line and a beep say to press `u`, add
the missing `m`, then `t` again.

It writes the same `~/logs/rover_<time>.json` as `rover_log.py teach
--cols`, so the mission and the camera app need nothing new. The map
comes from the camera app's `plot_maps_config.py`. The search order is
`--maps-file`, then `$TURF_CAMERA_DIR`, then the usual folders under home.
`--rows R --cols C` works without a map file.

## Plots are `t` now, not `n`

`n` sits next to `m` (headland point), so one slip marked the wrong kind
of point. **`t` marks a plot**, in the window and in the terminal
(`rover_log.py teach`). Pressing `n` now marks nothing and shows a
reminder. `m`, `s`, `u` and `q` are unchanged.

## Coming back for a skipped plot

Click a grey (skipped) or red plot in the window. It gets a blue border
marked PICKED, the title reads `NEXT: R1_C4 ... (picked)`, and the next
`t` teaches it. After that the usual order carries on from where it was,
stepping over any plot that is already taught. Esc, `s`, or clicking it
again cancels the pick. A green (taught) plot can't be picked; `u` undoes
the last mark.

**The robot drives marks in the order they were taught.** A plot taught
late is driven late, straight from the mark before it. If other plots are
in the way, first mark headland points (`m`) around them, the same as a
turn. The window says this when you pick. A picked mark is saved with
`"out_of_order": true`, and its plot comes off the skipped list. Undoing
it puts it back on the list.

## rover_log.py

- **The teach logic is now one class, `TeachSession`.** The terminal
  (`rover_log.py teach` and `drive`) and the window both use it, so there
  is one copy of how a mark is taken, named, refused, undone and saved.
  The terminal looks and works as before.
- **The teach file is saved after every mark, skip and undo** (written to a
  temporary file, then renamed). A crash or a flat battery mid-teach no
  longer loses the block.
- **Fixed: `u` after `s`.** Undoing a mark that came before a skip used to
  step the plot name back by one only, so the next plot got the wrong
  name. `u` now undoes the last mark *or* skip, and the names go back to
  exactly where they were.
- **Skipped plots are listed** in the teach file (`grid.skipped`).
- **The next plot steps over plots already taught** (after a pick), so no
  plot is taught twice.
- `pyserial` is only needed when reading the GNSS ports directly, so
  `--demo` runs on a laptop without it.

# Later on 20 Nov: straight rows, curved headland turns, commissioning

Written for the Dallas Amiga (4 ft track, heavier) that the GNSS kit is
moving to. It is tested in simulation only: the College Station turf model
(12 Nov calibration) plus a better-turning model. Neither the curves nor
the commissioning script has driven the real machine yet.

## Straight rows (`STRAIGHT_ROWS = True`)

- **Plots are never turned on.** There is no squaring-up turn on arrival,
  and no turn in place at the start of a leg that begins on a plot. The
  robot stops on the plot facing the way it drove in, and that angle goes
  in the run log and metadata (`heading_err_deg`).
- **A leg that would need a turn in place inside the rows is not driven.**
  If it is more than 30° off (`NO_PIVOT_MAX_DEG`), the run stops with
  "turn it by hand, then resume".
- **Gentle rolling corrections stay**, only when more than 1.5 cm off the
  line, as before.
- **`plan` flags any plot taught more than 5° off its row line.** Its
  image would come out rotated by that much.
- **All turning now happens at headland points.**

## Curved headland turns (`HEADLAND_TURN = "arc"`)

Teaching is unchanged: `m` just past the last plot (the run-out point),
and `m` on the next row's line facing down it (the lead-in point).

- **The mission joins them with one planned curve.** It is the shortest
  forward path of radius `ARC_RADIUS_M` between the two poses (a Dubins
  path). For the adjacent row it is a "bulb" turn: swing slightly away,
  loop round, come in straight. It never pivots.
- **From the last plot it drives straight through the run-out point
  without stopping**, follows the curve, and stops on the lead-in point,
  squaring up there (a headland point, so a small turn is allowed).
- **The curve is followed closed loop** with pure pursuit along the path,
  using GPS every tick. The command is scaled by `ARC_YAW_EFFICIENCY`
  (how much of a commanded turn the turf gives).
- **It stops rather than wanders.** More than 0.6 m off the curve
  (`ARC_MAX_DEV_M`), facing more than 75° off it, or no progress for
  15 s: the run stops.
- **`plan` and the mission start print each turn:** its length, how far
  it reaches past the run-out point and to each side, and a warning if the
  curved part passes within 1.2 m of a plot.
- **Run log:** the run-out point gets the result `passed`.
- **`HEADLAND_TURN = "pivot"`** goes back to stop-and-turn at each point.

Headland room needed for a turn into the adjacent row (1.22 m):

| `ARC_RADIUS_M` | past the run-out point | to the sides |
|---|---|---|
| 1.5 m | 3.6 m | 0.9 / 2.1 m |
| 2.0 m | 5.0 m | 1.4 / 2.6 m |
| 2.5 m | 6.4 m | 1.9 / 3.1 m |

**In simulation:**

| Turf model | Result |
|---|---|
| College Station (~18% of the turn, 1 ft track) | A 2 m curve at 300 mm/s cannot be held: it would need more than the 600 mrad/s command limit, and the run stops. At 150 mm/s with the efficiency known, it holds. The 12 Nov baseline test keeps pivot turns |
| 50% (standing in for the 4 ft Dallas machine) | 1.5–2 m curves complete. No rotation on any plot. Plots within 2 cm along and 4 cm across once the rolling floor suits the turf |

## Machine profile: `~/amiga_vehicle.json`

- **Each machine's measured numbers live in a profile file**, not in code.
  `vehicle.py` loads it (or `$AMIGA_PROFILE`; `none` ignores it). Its `nav`
  values replace the same-named constants in `amiga_nav.py`, and unknown
  names are reported.
- **No profile means the built-in College Station values.**
- **`plan` and every mission print which machine they run as.**
- **New: `ANTENNA_LATERAL_M`**, the antenna's distance left of the
  centreline. Zero on the College Station mast; matters if the Dallas mast
  goes left-right. The antenna geometry is applied in one place
  (`vehicle.centre_shift`), which both teach and replay use.

## Command ramps against mast swing

- **The turn rate is ramped both ways** (`ANG_SLEW_MRAD_S2`, default
  1200).
- **Forward speed is ramped up** (`LIN_ACCEL_MM_S2`, default 500).
  Slowing down is never delayed, and stops (anything but AUTO_ACTIVE) go
  out at once.
- **Pulse turns at headland points are lengthened** by the ramp time, so
  they still turn.
- **`None` turns a ramp off.** `commission.py swing` measures the right
  values.

## Fixed: a controller that gave up was counted as arrived

When the point controller gave up on a leg (`ABORT …`, a stalled final
turn), the drive loop still reported "complete" and the mission went on to
the next mark. Failed endings (`STOPPED`, `ABORT`, `STALLED`) now stop the
run.

## commission.py (new): measure a machine, write its profile

Run on open ground after the kit goes onto the Dallas Amiga. Each motion
step says how much space it needs and asks first.

| Step | Drives | Measures |
|---|---|---|
| `check` | nothing | fix, heading, CAN, Dashboard state, which profile is loaded |
| `heading` | 5 m straight forward and back | receiver heading offset; says if the mast is left-right |
| `centre` | ~300° in place each way | antenna forward and sideways offset (left and right spins cancel the pivot walk), and the walk itself |
| `breakaway` | creeping steps | slowest speed and slowest in-place turn that move it → `CREEP_SPEED_MM_S`, `ANGULAR_MIN_MRAD_S`, turn rates |
| `yaw` | ~9 m of rolling turns | `ARC_YAW_EFFICIENCY`, `ANGULAR_MIN_ROLLING_MRAD_S` |
| `swing` | 45° turns and short starts with different ramps | leftover mast swing → `ANG_SLEW_MRAD_S2`, `LIN_ACCEL_MM_S2` |
| `arc` | curve laps at 3 / 2.5 / 2 / 1.5 m | tightest radius held within 15 cm → `ARC_RADIUS_M`, `ARC_SPEED_MM_S` (falls back to pivot turns if none) |
| `course` | 2 rows × 4 fake plots from where it stands, with a curved turn | a real mission end to end; tape the chalked spots |

- **`all`** runs them in order, then `report` and `save`.
- **Results accumulate** in `~/logs/commission_<machine>.json`. Steps can
  be re-run singly, and later steps use what earlier ones measured.
- **`--sim`** runs it against `sim_amiga.py`, a simulated machine with
  hidden true properties, so the script can be tried on a laptop.
